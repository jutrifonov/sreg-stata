# Testing the native port

Run from the repository root:

```sh
python3 tools/test.py
```

Requires R, Python 3.8 or newer for development orchestration, and a licensed
Stata 14.2 or newer executable. Set `STATA_BIN` or use `--stata /path/to/stata`
if it is not named `stata-mp`, `stata-se` or `stata` on PATH. The installed
Stata package itself needs neither Python nor R.

Install R development dependencies once:

```r
install.packages(c("dplyr", "tidyr", "purrr", "extraDistr", "rlang", "cli",
                   "ggplot2", "viridis", "testthat", "haven", "knitr", "rmarkdown"))
```

The runner:

1. Verifies SHA-256 checksums of every vendored upstream source file.
2. Installs that exact R package in `.build/rlib`.
3. Runs all original testthat files, unchanged, plus the exported function
   examples. A development wrapper records estimator inputs, outputs and
   warnings without changing the returned results or original assertions.
4. Exports fixed input data and Stata assertions for every transferable
   estimator call. This includes successful calls and expected errors.
5. Runs native Stata against those fixtures and compares estimates, standard
   errors, z statistics, normal p-values, confidence intervals, warnings,
   sample counts, adjustment status and mixed component estimates/variances.
6. Runs the direct internal-helper translations, native interface tests,
   plotting tests and analytic covariance tests.
7. Writes `.build/verification.json`; any required failure exits nonzero.

The baseline contains 55 test cases and 563 assertions at the pinned commit.
Before documentation examples, those tests call the public estimator 240
times. Eleven calls validate R list/character container behavior; native
numeric-variable tests cover the relevant Stata interface. The other 229
are replayed directly. Counts including examples are in the latest report.

Numerical comparisons use absolute error at most `1e-8*(1+abs(R value))`.
Analytic helper/covariance comparisons and exact interface equivalences use
tighter tolerances. There is no requirement for R and Stata random seeds to
produce identical streams: shared estimation fixtures contain the actual
values generated by R.

`python3 tools/test.py --r-only` verifies only the R baseline and explicitly
does not mark native Stata verification complete. `--reuse-r` is available
for local iteration after a successful baseline run. Use the full command
for release verification. Stata batch exit status alone is insufficient:
the runner also requires end-of-suite markers and checks each parity row.

## Coverage boundaries

The original tests include generator, internal helper, output and R object
checks. Replaying public estimator calls is not a claim that every original
assertion has a literal Stata translation. See `tests/parity/coverage.md` for
the explicit mapping. In particular, the native generator is still pending;
generator-only tests currently establish the R baseline only.

Do not edit `tests/upstream` when fixing the port. It is a verbatim snapshot
of the reference package (excluding Git metadata and GitHub artifacts).
Update the reference commit, checksums and coverage together when intentionally
upgrading the R reference. Generated fixtures, raw logs and runtime libraries
are build artifacts and are not included in the installation package.

## CI

The GitHub workflow runs the R baseline on hosted runners. Full native tests
can be manually dispatched to a self-hosted runner labeled `stata`, with R,
Python and a licensed Stata already installed. Absence of such a runner is
not a passing native test. Local verification is recorded separately.
